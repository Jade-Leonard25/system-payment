# server

To install dependencies:

```bash
bun install
```

To run:

```bash
bun run
```

To type check:

```bash
bun check
```

To apply pending local D1 migrations and seed 1,000 product keys:

```bash
bun run seed
```

Each regular seed run adds 1,000 new keys and skips selectors that already exist. Run `bun run seed --remote` to add them to remote D1, or `bun run seed` to add them to local D1. The key format supports at most 46,656 unique selectors. Generated keys are saved to a git-ignored `seeded-keys-*.txt` file. Key values are also stored in D1 so the admin dashboard can display them; this is less secure than storing hashes alone, so protect database access and keep the export private. To import an existing key export, run `bun run seed --import-existing ./seeded-keys-<id>.txt --remote`.

Key activation is public and does not require an account: send `POST /api/key-products/activate` with JSON body `{"key":"abc-def-123"}`. The first successful activation changes the key status from `active` to `activated`. After activation, register an administrator with `POST /api/key-products/register-admin` and JSON body `{"key":"abc-def-123","name":"Admin Name","email":"admin@example.com","password":"your-password"}`. Registration atomically reserves the key, creates the Better Auth account, links the key in `user_admin.key_product_id`, grants the admin role, and marks the key `redeemed`. A redeemed key cannot register another account. Administrators can create keys with `POST /api/key-products`, list up to 1,000 key records with `GET /api/key-products?limit=1000`, and revoke a key with `DELETE /api/key-products/:id`. The backend serves a testing dashboard at `/` showing full keys to signed-in administrators.

Run `bun fmt` to format the code.

This project was created using `bun init` in bun v1.4.4. [Bun](https://bun.com) is a fast all-in-one JavaScript runtime.

## Attendance batch scanning

The local JSON scan-and-compute endpoint, request format, review behavior,
database migration, and payroll-rule limitations are documented in
[ATTENDANCE-SCAN-PIPELINE.md](./ATTENDANCE-SCAN-PIPELINE.md).

## API endpoints

The complete route reference, including authentication requirements, request
fields, behavior, and response summaries for each mounted endpoint, is in
[API-ENDPOINTS.md](./API-ENDPOINTS.md).

Employee roster imports convert CSV/Excel data to JSON in the frontend and
send it to `POST /api/employees/batch` in atomic batches of up to 1,000
employees. The direct import supports up to 100,000 rows without rendering
them in the spreadsheet editor. Employee IDs are generated by the backend and
kept out of the accountant-facing columns.

## Frontend source archive

The frontend project has been copied to [frontend/](./frontend/)
for reference. It is not part of Worker deployment: Wrangler bundles the
configured `main.ts` entry point and its imports, and uploads static assets
only from the configured `public/` directory. Do not change the `main` or
`assets.directory` settings to point to `frontend/`.

The shared frontend sidebar is implemented in
[app-sidebar.jsx](./frontend/src/components/app-sidebar.jsx). Overview and
Payroll & Employees and Transactions are routed modules. Audit log is available
to members with `audit.view`, and Transactions uses `ledger.view`,
`ledger.create`, `ledger.post`, and `ledger.reverse`. Other planned accounting
modules remain disabled until their screens and permissions exist.
